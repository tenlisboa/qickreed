<objective>
Harden admin Server Action defense-in-depth in `src/app/(authenticated)/admin/texts/actions.ts` so a logged-in `member` cannot reach any Supabase mutating call by POSTing directly to the action endpoint (bypassing `admin/layout.tsx`), migrate all 5 actions in that file to the codebase's `ActionResult<T>` contract (AD-001), update all 7 caller sites to unwrap the new shape, add a Pino `warn` log to `checkAdminAccess()` for non-admin block telemetry, and add a vitest regression test file that locks the new auth ordering and documents the deliberate open-read policy of `getTextById`.

Purpose: Close the application-layer auth gap so non-admins never reach RLS in the first place, and stop the misleading `success: true` on RLS-rejected mutations by adopting the project's canonical return shape. SEC-01 (mutating actions call `checkAdminAccess()` first) and SEC-02 (reads policy deliberately documented) are both closed by this single tightly-coupled slice.

Output:
- `src/utils/auth/admin.ts` — `checkAdminAccess()` emits a Pino `warn` log before the non-admin redirect (D-02).
- `src/app/(authenticated)/admin/texts/actions.ts` — all 5 actions return `ActionResult<T>` via `ok()`/`fail()`; `createText`, `updateText`, `deleteText`, `getTexts` call `await checkAdminAccess()` first (D-01, D-03); `getTextById` stays public-authenticated-read (D-04).
- 7 caller pages/modal updated to unwrap `result.error` vs `result.data` (D-09).
- New `src/__tests__/admin-texts-actions.security.test.ts` — covers all 5 categories in D-10 with the supabase-level-only mocking strategy from D-11.

## Artifacts this phase produces
Exports newly created: **none** — `checkAdminAccess` is modified in place (not new); `createText` / `updateText` / `deleteText` / `getTexts` / `getTextById` change return type but keep their names and signatures (param shape unchanged, return type changes to `ActionResult<T>`).
New source files:
- `src/__tests__/admin-texts-actions.security.test.ts` (new vitest regression test)
New test cases (named `describe`/`it` blocks):
- `createText` — admin succeeds → `ok({ id })` + `revalidatePath` called; non-admin blocked → no Supabase insert observed + action rejects (`NEXT_REDIRECT`); Supabase insert error → `fail("db_error", ...)`.
- `updateText` — admin succeeds → `ok(null)` + `revalidatePath` called; non-admin blocked → no Supabase update observed; Supabase error → `fail("db_error", ...)`.
- `deleteText` — admin succeeds → `ok(null)` + `revalidatePath` called; non-admin blocked → no Supabase delete observed; `checkTextInUse` true → `fail("validation", ...)` (pt-BR string); Supabase error → `fail("db_error", ...)`.
- `getTexts` — admin succeeds → `ok(TextListResult)`; non-admin blocked → no Supabase select on `text` observed; Supabase error → `fail("db_error", ...)`.
- `getTextById` — authenticated non-admin receives `ok(Text)` row (documents D-04 deliberate open-read as a regression test); missing row → `ok(null)`; Supabase error → `fail("db_error", ...)`.
</objective>
